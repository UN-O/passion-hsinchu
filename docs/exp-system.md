## 分區

三區，固定常數，不進資料庫：

| key | 名稱 |
| --- | --- |
| `bee` | 蜜蜂 |
| `clownfish` | 小丑魚 |
| `groundhog` | 土撥鼠 |

## 資料模型

分數是**區的總分**，不追到個人。

新表 `exp_record`：

- `id`
- `region` — `bee` / `clownfish` / `groundhog`
- `amount` — 正整數，**不會有扣分**
- `reason` — nullable
- `createdBy` — user id
- `createdByName` — 當下姓名快照（工作人員之後被移出名單，記錄仍要看得出是誰加的）
- `createdAt`

多選分區時**一區寫一列**。各區總分用 `sum` 聚合，不另存冗餘欄位，才不會有兩份數字對不起來的問題。

修正與刪除都直接對這張表操作（因為不用扣分，不需要沖銷列）。

## 後台 `/admin/points`

`requireStaff()` 保護。

### 沈浸式加分流程

1. 「開始加分」進入流程
2. 三區大按鈕，**可多選**
3. 分數：preset 快捷鍵 `200 / 400 / 500 / 1000 / 2000`，另有數字鍵盤可自行輸入
4. 原因（optional）：preset 按鈕 + 自由輸入 textarea
5. 完成回饋

原因 preset（`大隊長加分` 為新增，其餘沿用 2025）：

```
大隊長加分、PERK、bonus (小)、bonus (中)、bonus (大)、反應熱烈、
小競賽、小隊呼、最早到場、對牧者有禮貌、團隊合作、創意表現、
準時集合、環境整潔、優秀表現、MVP或特殊貢獻、闖關勝利
```

2025 的 preset 每個都綁一個固定分數，這裡刻意拆開：原因只是標籤，分數獨立選，
因為同一個原因在不同情境給的分數不一定一樣。

## 注意事項

- **額度**：學生端分數頁會查 DB，且會被重複重整。查詢要走 tag 化快取，加分／修正／刪除時才
  失效——公開或半公開頁面直接查 DB 是這個專案已經踩過的坑。
- **樣式**：依 `style.md`。brand-yellow 只用在主要按鈕、選中狀態、分數這種強調處；
  完成回饋做成簡潔的狀態變化，不是裝飾性動畫；不用 emoji（「完成」用文字或 SVG，不要 ✅ 字元）。
- 圖表配色與座標軸規則見 `dataviz` skill，動工前先讀。
